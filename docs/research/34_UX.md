# 34_UX — Editor UX architecture (the engine↔UI contract)

> Status: PARTIAL (v0.1 — wave-3 depth pass 2026-09-24).

Scope: NOT visual design. This doc defines what the ENGINE must expose so that any
shell (Tauri web UI [17], desktop, CLI, agent [26][27]) can deliver editor-grade UX:
interaction-state model, reactivity over the command log, preview/clocking rules,
keyboard-first grammar. Editor-by-editor survey lives in 02_EXISTING_EDITORS.md
(reference, not duplicated); timeline verbs in 03/20; agent gating in 26.

Established constraints respected: exact rational time (ADR-007), explicit-id
deterministic command log with inverse-command undo (E-003), one command API for
human + AI (ADR-010), gap-buffer primary structure + derived index (ADR-011).

## 1. Interaction-state model (playhead / selection / hover / drafts)

Three orthogonal state classes — the classic NLE split, re-derived from surveyed
editors [02]:

- **Authoritative document state** — lives in the engine. Changed ONLY by committed
  commands. Every entity carries an explicit id (E-003 schema lesson 1: "every id
  must be explicit in the log"; apply-time id derivation makes replay
  interpretation-dependent).
- **Selection / scope state** — WHICH ids a next command will touch. OpenCut classic
  keeps selection snapshots inside each Command so undo restores selection [S-102];
  Kdenlive's TimelineModel exposes selection through the model, not the widget layer
  [S-2b4]. Engine implication: selection is a first-class engine query
  (`selected_ids()`, `select(ids)`), NOT view-local state — agents need it too [26].
- **Transient UI state** — hover, drag ghost, marquee, scroll, zoom. Belongs to the
  shell, must be recoverable (`hover` = derived query, never logged).

**Drag = command draft.** A drag gesture does not mutate the document; it produces a
draft that is (a) rendered as a preview overlay, (b) validated continuously against
engine invariants, (c) committed as one command (or batch) on release, (d) converted
to an inverse-command for undo. Evidence: Kdenlive `request*Action` API returns bool
with nothing-modified-on-failure — validate-then-apply is engine-owned [S-2b4];
Cutlass makes dry-run the DEFAULT for agent-initiated edits with a draft/preview
step [S-104]; Clypra keeps a `timelineDraftStore` separated from committed stores
[S-105]; ADR-010 fixes the same shape: `validate→preview→approve→apply→receipt`.

Draft-state API the engine must own (shell is free to cache):
- `preview(command) -> PreviewResult { valid, conflicts, projected_state_diff }`
- snapping is an engine service, not UI decoration: `snap_candidates(track, tick,
  exclude_ids)` (Kdenlive ships a SnapModel + "Go to Next/Previous Snap Point"
  navigation keys [S-3f0]) — snap math must use exact ticks (ADR-007), never fp px.
- hit-testing needs the derived interval index (ADR-011): `hit_test(track, tick)`,
  `items_overlapping(range)` — a gap buffer alone cannot answer "what is under the
  cursor at tick T" in O(log n).

## 2. Keyboard-first editing (verified: Kdenlive 26.08 manual [S-3f0])

Verified key bindings (Kdenlive 26.08 manual, shortcuts page):
- Playback: `J` rewind — re-press cycles speeds (−1×, −1.5×, −2×, −3×, −5.5×, −10×);
  `K` pause; `L` forward with the same 1×→10× cycling; `Space` play/stop;
  `←/→` 1 frame; `Shift+←/→` 1 s; `Alt+←/→` next/previous SNAP POINT (snapping is
  navigation, confirming snap points are queryable engine data); `Ctrl+Space` play
  zone; `Ctrl+Shift+Space` loop zone.
- Tools: `S` selection tool, `X` razor tool, `M` spacer tool, `Ctrl+A` select all,
  `Ctrl+Shift+A` deselect.
- Editing: trim-to-playhead ripple variants ("Cut, delete and remove the empty
  space use Ripple Trim to Playhead"), `B` overwrite clip zone, `Shift+I/O` go to
  zone start/end.
- Undo: `Ctrl+Z` / `Ctrl+Shift+Z` (Qt stack, see S-2b4 DocUndoStack).
- "Start Preview Render" = `Shift+Return` — preview rendering is a user-visible,
  interruptible operation (§4).

Shotcut exposes the same verb set as ~30 named QUndoCommand subclasses (Append/
Insert/Overwrite/Lift/Remove/Move/Trim/Split/Fade/AddTransition/DetachAudio/
Replace/AlignClips…) [S-2b5]; Flowblade makes INSERT the default idiom vs Shotcut's
toolbox idiom — same engine, different interaction policy [S-2b7]. ENGINE RULE:
every keyboard edit resolves to the SAME command type as its drag/CLI/agent
equivalent; keys are only a command-argument resolver. UNVERIFIED: Shotcut's own
shortcut table (shotcut.org page 404 this session, NOT-FOUND log).

## 3. Reactivity: UI as a subscriber of the command log

- **State = fold(log).** E-003 proved snapshot+suffix replay == full replay with
  hash equality (P3) and JSON round-trip replay (P1b). The UI therefore has two
  legal rehydration paths: (a) subscribe to committed-command events and apply
  incrementally; (b) fetch snapshot + replay suffix. Both must produce identical
  hashes — that property is already enforced (E-003 9/9).
- **Event stream the engine must emit** (minimum): `CommandCommitted{id, batch_id,
  label, inverse_available}`, `CommandRejected{id, reason}`, `CommandUndone{...}`,
  `TransactionOpened/Closed`, `SelectionChanged`, `MediaProbed/Imported`,
  `RenderProgress{job_id, stage, done, total}`, `ProjectSnapshot{...}`. Events carry
  ids, never floats (ADR-007/E-003).
- **Optimistic UI is safe only as draft rendering.** Shell may render a validated
  draft instantly, but the authoritative switch happens at commit; on rejection the
  draft is discarded (Kdenlive's nothing-modified-on-failure is the non-optimistic
  reference behavior [S-2b4]). Never speculative-apply to the model.
- **Undo UX.** Grouping: undo granularity = transaction/batch (ADR-010), not raw
  command; a 12-clip ripple = ONE undo entry. Labels: every transaction carries a
  human label for the undo menu (engine field, e.g. `Move 3 clips`); Kdenlive shows
  named actions in its undo stack and Shotcut names each QUndoCommand [S-2b4][S-2b5].
  Undo = inverse commands with saved-state where needed (E-003 lesson 2:
  RemoveClip inverse needs prior state). Persisted history across sessions is
  cheap for us and NOT done by Kdenlive/Shotcut (session-local lambda pairs /
  QUndoStack, discarded) [S-2b4][S-2b5] — a differentiator, gated on E-003 replay.
- **Progress events** must be engine-native: import probe, analysis (26), render
  (E-007b segment pipeline), upload (36). UX shells render them uniformly.

## 4. Preview architecture

- **Scrub latency budget:** doc 18 sets the app budget; ADR-011 names "scrub burst
  ~1 ms (doc 18)" as the timeline-structure revisit trigger. Preview goal: pointer
  → frame displayed with no intermediate layout pass; hit-test + seek dispatch are
  O(log n) against the derived index (ADR-011).
- **Quality ladder** (user-selectable, engine-defined):
  1. proxy media (half/quarter res) + skipped effects;
  2. full-res draft (fast filter paths, nearest color transforms);
  3. full quality (used at export / final scrub frame after settle).
  Precedent: Kdenlive's explicit "Start Preview Render" (renders an internal
  preview stream ahead of the playhead) [S-3f0]; E-007/E-007b prove stream-copy
  segment reuse is 7–12× cheaper than re-encode at 1080p — preview cache segments
  and export segments should be the SAME artifacts.
- **A/V clock sync (playhead-synced):** VERIFIED tolerance numbers — EBU R37
  (2007): per-stage accuracy "Audio 5 ms early … to 15 ms late"; end-to-end
  "≤ 40 ms / ≤ 60 ms" (sound before/after picture), derived from 50%-observer
  perceptibility tests [S-3f1]. The oft-quoted "±22 ms" lip-sync figure was NOT
  found in an authoritative fetchable source this session → UNVERIFIED (see list).
  Engine rules: video frame presentation is scheduled by the audio clock (audio
  drifts less across devices); audio continues across frame-boundary stalls (never
  gate audio on video readiness); seek re-primes both clocks exactly (rational
  ticks, ADR-007); any resampler/vanishing-buffer path must preserve PTS integrity
  (doc 04/05 pitfalls).

## 5. Engine↔UX contract (checklist)

The engine MUST expose: (1) versioned command schema + validation + inverse map
(E-003/ADR-010); (2) event stream (§3) with labels and batch ids; (3) state queries
— selection set, hit_test, snap_candidates, items_overlapping, track/clip extents
(all in exact ticks; hit-test/snap backed by the derived index, ADR-011);
(4) preview control — play/pause/rate/seek, quality tier set, preview-cache
invalidation hints (which ranges a command dirties; ties to E-007 smart render);
(5) progress events for probe/import/analysis/render/upload; (6) per-transaction
undo labels; (7) capability probing (codecs/hw accel → UI grays out unsupported
exports, doc 04/11). Everything else (themes, dialogs, layout, gestures) is shell.

## 6. Explicitly NOT built in v1

- **No custom UI framework / toolkit.** Use platform UI kits behind the command
  API: Tauri+web [17], or native (GPUI in OpenCut's rewrite is that project's shell
  choice [S-101]); engine ships no widgets. Justification: every surveyed new-gen
  editor builds shells on existing stacks (React/Svelte/Slint/Qt) while the
  differentiator is the core+command layer [02].
- No skinning/theming system, no in-engine text/shape editor (titles/captions are
  platform-authored, engine receives timed text payloads — 23), no collaboration
  CRDT layer, no scripting sandbox (separate docs 28/29 tracks).
- No touch-gesture grammar beyond standard shells — un-researched, not claimed.
