# CROSS-PLATFORM CONFORMANCE PLAN (v1, 2026-09-26)

> Directive deliverable: how the engine proves the SAME semantics on every platform leg
> instead of claiming them. Ground rules: (a) VALIDATION levels ascend only on real
> evidence (VALIDATION_AUDIT §1) — SOFTWARE → DEVICE → REAL_GPU → CROSS_PLATFORM;
> (b) a platform leg "conforms" when it passes the same semantic contract suites as the
> software reference leg, with tolerances declared in advance (§6); (c) no leg may pass
> by silently degrading — degradation is capability-gated and user-visible
> (ARCHITECTURE_AUDIT #5). Parents: FINAL_ARCHITECTURE_WHITEPAPER §5/§6, ENGINE_BUILD_PLAN
> Wave 8; consumes every spec suite (ME/D/RG/E/P).

## 1. The legs and their reference implementations

| Leg | Shell | Media adapter | GPU path | Storage | Reference evidence today |
|---|---|---|---|---|---|
| L-0 Headless/CLI | ove-cli | FFmpeg-SW (ove-decode/ove-encode) | software raster (CPU) | filesystem | the vertical slice itself (Waves 1–5) |
| L-1 Desktop | Tauri (E-006b pending) | FFmpeg-SW via IPC/CDYLIB | wgpu (E-005 promotion) | filesystem | E-004a/b FFI; E-006 browser-leg |
| L-2 Android | Kotlin + UniFFI 0.32 (E-004c pending) | MediaCodec (adapter) | Surface/GL import (later) | app storage + SAF | E-004b 8/8 JVM roundtrip only |
| L-3 Browser | WASM core + TS | WebCodecs + mediabunny (probe/mux) | WebGL2 → WebGPU (feature-gated) | OPFS + File System Access | E-001 48/48 decode leg (software GPU) |

L-0 is the conformance REFERENCE: every suite is defined to run there first, committed,
CI-green; the other legs reuse the corpus and assert the same outcomes.

## 2. The conformance corpus (single source of truth)

One committed corpus, generated by script, hash-registered (no per-leg fixtures):

| Corpus item | Content | Used by |
|---|---|---|
| C-media-1 | 8s 24fps CFR H.264 + AAC, 640×360, Bt709 tags | D-1..D-12, E-1..E-7 |
| C-media-2 | 29.97fps NTSC clip (non-integer-rate axis) | D-1, P3b-axis rules, E-2 |
| C-media-3 | VFR screen recording (pts gaps) | D-2, D-12, RG-2 |
| C-media-4 | 10-bit HEVC sample (color-tags stress) | D-10, RG-7 |
| C-media-5 | corrupt/truncated/tiny trio | D-8 error model |
| C-proj-1..3 | saved .ove projects incl. batches, undo markers, keyframes | P-1..P-8 |
| C-gold-* | golden frames (PNG+hash) + golden MP4s (sha256 + ffprobe JSON) | RG-2, E-5, ME-5 |

Rule: an adapter that cannot consume the corpus (codec/gap) declares it as a capability
limit and runs the corpus subset it can — the SUBSET IS RECORDED in the leg's conformance
report, never skipped silently (D-9 honesty rule generalized).

## 3. What must be IDENTICAL on every leg (engine-core invariants)

| Invariant | Suite | Identity criterion |
|---|---|---|
| Time arithmetic | ove-time suite ported to each binding | exact rational results (no fp) |
| Command semantics | ME-1/ME-2 via each shell's command path | state_hash equal to L-0 |
| Replay determinism | ME-1, P-2 (kill/reopen) | hash-equal fold |
| Project bytes | P-1/P-5/P-6 | manifest+log byte-canonical; assets by content hash |
| Command schema | ME-7 | float payload rejected at EVERY boundary (TS/JNI/WASM too) |
| Undo/redo | ME-2 | apply→inverse→apply identity |

These run through each shell's real boundary (Kotlin JNI, TS/WASM, Tauri IPC) — not
through Rust-side unit tests alone. That is the lesson of E-004a/b: the boundary is the
bug source.

## 4. What is ALLOWED to differ (declared divergence points)

| Divergence | Mechanism | Bound |
|---|---|---|
| Codec/container availability | DecoderCaps / EncoderCaps | caps published; unsupported → typed Unsupported, never hidden downgrade (D-9) |
| Seek granularity (hw keyframe-snap) | SeekMode caps | Snap results are identical BY CONSTRUCTION to L-0's Snap; Exact must still equal L-0 |
| Pixel-format handling (hw outputs NV12 etc.) | adapter converts at FrameEnvelope boundary | color tags + geometry must match; bytes may differ pre-convert |
| Color conversion backend | ove-render owns conversion once | golden-frame hash within §6 tolerance |
| GPU rendering | wgpu vs platform paths | same RenderPlan; RG-2 golden parity per §6 |
| Performance | per-leg benches (separate) | budgets from doc 32; never merged into correctness suites |

## 5. Per-leg conformance gates (what flips VALIDATION levels)

| Leg | To ascend | Must pass | Evidence artifact committed |
|---|---|---|---|
| L-0 | SOFTWARE (done when slice gate passes) | ME-1..ME-8 + D-1..D-12 + RG-1..RG-7 + E-1..E-7 + P-1..P-8 | CI green; golden hashes |
| L-1 desktop | SOFTWARE→SOFTWARE(IPC) then REAL_GPU (with L-0 GPU) | E-006b transport bench; frames-never-JSON rule at both edges; wgpu golden parity | E-006b result + bench record; RG-2 GPU hashes |
| L-2 Android | NONE→DEVICE | E-004c on-device JNI roundtrip (UniFFI 0.32); MediaCodec adapter D-1/D-4/D-5 subset; FGS checkpoint/resume drill (R-07) at segment granularity (E-6 pattern) | device log + conformance report (subset recorded) |
| L-3 browser | SOFTWARE(decode leg)→SOFTWARE(engine) | WASM core ME-1/ME-2/P-suite on OPFS; WebCodecs D-suite subset; **runtime feature-detection matrix** (§7); importExternalTexture behaviour (Q-02) recorded | per-browser matrix run (Chromium/FF/Safari where available) |

CROSS_PLATFORM (top level) = L-0 + at least two of {L-1, L-2, L-3} passing their suites
with recorded subsets, AND the §3 invariant table green on every leg, AND no silent
degradation anywhere. Until then the word CROSS_PLATFORM appears only as a target, never
as a status.

## 6. Tolerance policy (declared in advance, not negotiated after failures)

| Comparison | Policy |
|---|---|
| Time/pts/duration, state hashes, command replay | **bit-exact** (rationals + canonical serialization; no tolerance exists) |
| Project bytes (manifest/log) | bit-exact canonical form |
| Software-render frames (same backend) | bit-exact (golden hash) |
| GPU-rendered frames vs software reference | pixel-diff ≤ declared per-channel epsilon (default 1/255 on 8-bit) + same color tags; ANY diff must be attributable to documented GPU path semantics; if parity cannot hold, the pass is split so GPU-unsafe passes fall back to software (plan-level decision, RENDER_GRAPH_SPEC §5) |
| Encoded outputs across encoder backends | structural identity (E-1..E-4) only; byte-identity required only SW-vs-SW with pinned versions (ENCODER_SPEC §6) |
| Audio/video sync | sample-exact (audio sample count is the authority; no tolerance) |

## 7. Browser feature-detection matrix (mandatory, user-visible)

| Capability | Chromium | Firefox | Safari | Detection | Degraded mode if absent |
|---|---|---|---|---|---|
| WebCodecs decode | yes | yes (desktop/Android; versioned) | yes (16.4+) | `'VideoDecoder' in window` | mediabunny MSE fallback or file-import refusal (typed) |
| WebCodecs encode | yes | partial (versioned) | partial | `VideoEncoder` + codec `isConfigSupported` | export via server/none — never a silent empty output |
| WebGPU | yes | yes (versioned) | yes (26+) | `navigator.gpu.requestAdapter()` | WebGL2 raster path (declared in UI) |
| OPFS sync handles | yes | yes (versioned) | yes (versioned) | `FileSystemSyncAccessHandle` | in-memory + download/export |
| Workers + WASM SIMD | yes | yes | yes | feature probes | single-thread mode |

Rules: (1) detection runs at runtime, per-origin, every session; (2) the app surfaces a
capability report (same DecoderCaps/CoderCaps honesty as the engine); (3) Firefox-Android
and iOS <16.4 are EXPLICITLY out of the support matrix (R-02/R-03) — listed as
unconforming, not silently attempted; (4) Q-13 (WebKitGTK WebCodecs) tracked for the
Tauri-WebGPU leg; until resolved, Linux Tauri = FFmpeg-SW media leg (that is ADR-002's
adapter story, not a browser claim).

## 8. Failure protocol (when a leg fails a suite)

1. The failure is recorded in the leg's conformance report with corpus ID + diff class
   (per §6 categories) — a failing leg is EVIDENCE, not an embarrassment (E-001's
   SwiftShader block is the model).
2. Classification: (a) adapter bug → fix adapter; (b) contract bug (spec disagrees with
   platform reality) → spec ADR amendment + reopen trigger recorded
   (ARCHITECTURE_AUDIT §3 falsification conditions); (c) platform limitation →
   capability-gated degradation + matrix update (§7), user-visible.
3. No suite is weakened to make a leg pass. Tolerances change only via §6 amendment with
   a recorded reason and a re-run of the whole corpus on all legs.

## 9. Execution schedule (bound to ENGINE_BUILD_PLAN)

- Waves 1–5: build L-0 reference + corpus + suites (this is most of the work; §3
  invariants are enforced by construction through the real command path).
- Wave 6 (E-005 promotion): GPU parity per §6; adds REAL_GPU evidence on whichever
  hardware runners exist; SwiftShader results are never labelled REAL_GPU.
- Wave 8 (platform legs): E-004c (L-2), E-006b (L-1 transport), browser matrix (L-3);
  each produces a committed conformance report; ADR-002 residuals flip or falsify per §8.
- Ongoing: CI runs L-0 suites on every push; device/browser legs run on schedule/manual
  with artifacts committed (quota + hardware reality documented in doc 39/E-011).

## 10. What this plan does NOT promise

- No claim that any platform leg conforms today (only E-001's decode leg and E-004b's
  JVM boundary have evidence at all).
- No "write once run everywhere" claim for media execution — media adapters differ by
  design (ADR-002/003); what is universal is the CONTRACT (time, commands, project
  format, frame envelope, render plan), and that is exactly what §3 enforces.
- No performance parity claim; budgets are per-leg, bench-separated (R-14).
